## 一、架构与设计

| # | 问题 | 严重度 |
|---|------|:---:|
| 1 | `django_server` 是 session 级 autouse，每个 pytest 进程只启一个 Django。如果 `pytest-xdist -n 4` 并发，4 个 worker 各起一个 runserver 抢同一个 8000 端口——你怎么处理？ | 🔴 |
| 2 | `persistent_sku` 也是 session 级 autouse，创建 9999 库存的 SKU。跑 200 条测试没一个做库存扣减后回滚，万一哪天真用光了，后半段测试全假失败——你打算怎么兜底？ | 🔴 |
| 3 | conftest 里 `new_user`、`test_spu`、`test_sku`、`test_order` 全是 function 级，每跑一条创建一条。216 条用例 = 创建 216 个用户 + 数十个 SKU + 数十个订单。数据库会不会炸？你有清理吗？清理失败怎么办？ | 🔴 |
| 4 | `get_any_sku_id()` 每次调用都发一次 GET 拉全量 SKU 列表。order 模块里 `_create_order` 也调它——一个 TestOrderCreate 类 setUp 调一次，每个 test 再调一次，重复请求有没有缓存？ | 🟡 |
| 5 | conftest 的 `shared_category` 是 session 级，`shared_brand` 却是 module 级——同一个 test_goods.py 里既有 Category 又有 Brand，为什么要用不同 scope？故意设计还是忘了对齐？ | 🟡 |
