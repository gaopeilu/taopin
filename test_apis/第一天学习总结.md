# 第一天学习总结：从零写接口测试

## 一、HTTP 状态码 vs 业务 code

这俩不是同一个东西，位置和含义都不同：

```
HTTP 响应
│
├── 状态行:  HTTP/1.1 201 Created    ← HTTP 状态码（resp.status_code）
│
└── 响应体:  {
                "code": 200,          ← 业务 code（resp.json()["code"]）
                "message": "注册成功",
                "data": {...}
            }
```

| | HTTP 状态码 | 业务 code |
|------|------------|-----------|
| 位置 | 响应头 | JSON body 里 |
| 谁决定 | HTTP 协议 / DRF 框架 | 你自己写 |
| 成功值 | 200 或 201 | 项目里固定 200 |
| 失败值 | 400/401/403/404 | 项目里跟着 HTTP 走 |
| 断言 | `resp.status_code` | `resp.json()["code"]` |

**关键结论**：成功时两者可以不一样（如 201 vs 200），失败时这个项目里一样（400 vs 400），但完全可以不一样（大厂常用 400 + 10001 业务错误码）。

---

## 二、谁决定状态码

| 情况 | 谁决定的 | 示例 |
|------|----------|------|
| 序列化器校验失败 | **DRF 框架自动给 400** | 你没写任何 status |
| 没 token | **DRF 权限类自动 401** | `IsAuthenticated` 触发 |
| 没权限 | **DRF 权限类自动 403** | 普通用户调商家接口 |
| View 里 `status=xxx` | **你自己写的** | `status=status.HTTP_201_CREATED` |
| View 里没写 `status=` | **DRF 默认 200** | `return Response({...})` |

**DRF 框架自动返回的所有状态码**：200、400、401、403、404。其余如 201、204 以及手动的 400/403 需要自己写。

## 三、追查接口行为的四步法

```
你的测试请求
    │
    ▼
① urls.py ──→ 匹配到哪个 View？
    │
    ▼
② views.py ──→ 看的重点是：
      · serializer.is_valid(raise_exception=True) 还是手动 if/else？
      · return Response({...}, status=???) 成功状态码是多少？
      · permission_classes 是什么？
    │
    ├── 校验失败 → ③ serializers.py 搜 "raise ValidationError"
    │               每个 raise 就是一个异常场景
    │                    │
    │                    ├── 传字符串: {"code":400, "message":"xxx"}
    │                    └── 传字典:   {"code":400, "message":"key: xxx", "errors":{...}}
    │
    └── 校验通过 → 继续往下走 → 返回
```

---

## 四、ValidationError 字符串 vs 字典（核心坑点）

### 字典类型 → 有 message + errors

```python
raise serializers.ValidationError({"password_confirm": "两次密码不一致"})
```

响应：

```json
{
    "code": 400,
    "message": "password_confirm: 两次密码不一致",
    "errors": {"password_confirm": ["两次密码不一致"]}
}
```

### 字符串类型 → 只有 message

```python
raise serializers.ValidationError("用户名或密码错误")
```

响应：

```json
{
    "code": 400,
    "message": "non_field_errors: 用户名或密码错误",
    "errors": {"non_field_errors": ["用户名或密码错误"]}
}
```

**结论**：写断言前，必须去 serializers.py 看 `ValidationError()` 的参数类型，决定要不要断言 `errors` 字段。

---

## 五、APIException（401/403）→ detail 分支

权限类触发的异常（`NotAuthenticated`、`PermissionDenied`）走 exceptions.py 的 `detail` 分支，**不带 `non_field_errors:` 前缀**：

```json
{"code": 401, "message": "Authentication credentials were not provided."}
```

消息来自 DRF 框架源码，是你没写的。

---

## 六、异常处理的三层链路

```
① serializers.py
   raise ValidationError("xxx")
        │
        ▼
② DRF 框架（自动）
   400 + 默认格式 {"non_field_errors": ["xxx"]} 或 {"detail": "xxx"}
        │
        ▼
③ utils/exceptions.py（你定义的）
   重新打包成 {"code": 400, "message": "xxx", "errors": {...}}
```

**关键文件**：

| 文件 | 看什么 |
|------|--------|
| `dianshang/urls.py` | 路由前缀 |
| `apps/xxx/urls.py` | 具体接口路径 |
| `apps/xxx/views.py` | `status=xxx`、`permission_classes` |
| `apps/xxx/serializers.py` | 搜 `raise ValidationError` 找异常场景 |
| `utils/exceptions.py` | 错误响应统一格式 |

## 七、写测试用例的标准模板

### 每个接口测两类

| 类型 | 数量 | 说明 |
|------|------|------|
| 正常用例 | ≥1 | 合法参数，断言成功 |
| 异常用例 | 每个 raise 一个 | 去 serializers 搜 `raise ValidationError` |

### 每个用例断言三步

```python
# 1. HTTP 状态码
assert resp.status_code == 200

# 2. 业务 code
json_data = resp.json()
assert json_data["code"] == 200

# 3. 关键字段
assert "tokens" in json_data["data"]
assert json_data["data"]["user"]["username"] == "test111"
```

## 八、测试最佳实践

### 动态数据避免冲突

```python
import time
timestamp = int(time.time() * 1000)
username = f"test_{timestamp}"
```

### 先看再写

```python
resp = requests.post(url, json=body)
print(resp.status_code, resp.json())    # 看一眼真实返回
# 然后照着写断言
```

### Token 管理（不封装阶段）

```python
# 每个需要 token 的用例：先登录，拿 token
login_resp = requests.post(login_url, json=login_data)
token = login_resp.json()["data"]["tokens"]["access"]

# 带着 token 请求目标接口
headers = {"Authorization": f"Bearer {token}"}
resp = requests.get(target_url, headers=headers)
```

### 失败用例也做数据隔离

密码不一致这种异常用例，虽然不会写入数据库，但用户名也可能冲突（如果上次跑成功过）。同样加时间戳最安全。

## 九、今天踩过的坑

| 坑 | 原因 | 教训 |
|------|------|------|
| 断言 200，实际 201 | 注册成功返回 `status=201` | 先看 views.py 的 `return Response(..., status=xxx)` |
| 密码 "123456" 不合法 | `min_length=8` | 测试数据要满足**所有**字段校验，才能测到目标逻辑 |
| 猜错了错误结构 | 没看 `ValidationError` 的参数类型 | 字符串→无 errors，字典→有 errors |
| URL 少了个 s | `/user/me/` vs `/users/me/` | 对着 urls.py 复制路径 |
| 改了只读字段 username | `read_only_fields` | 先看 serializer 的 Meta 类 |
| 写错了响应结构 | 登录是 `data.user.username`，个人信息是 `data.username` | 登录多包了一层 user |
